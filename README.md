# Trial Activation Analysis
**Splendor Analytics Data Analyst Community Challenge**

## Overview

This project defines and measures **Trial Activation** for Splendor Analytics' 30-day free trial — identifying the specific in-app behaviours that signal a trialist has genuinely experienced the platform's core value, and building the data infrastructure to track activation at scale.

The dataset covers behavioural events from organisations that started their trial between January and March of last year. Approximately 1 in 5 trialists converts to a paying customer.

## Setup & Reproduction

### 1. Prerequisites
- Python 3.10+
- Git

### 2. Clone and set up

```bash
git clone <repo-url>
cd trial_activation_analysis

# Create virtual environment
python -m venv env

# Activate (Windows)
env\Scripts\activate

# Activate (macOS/Linux)
source env/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### 3. Add the data

Place the provided `DA task.csv` into `data/raw/`:

```
data/raw/DA task.csv
```

### 4. Run the notebooks in order

```bash
# Register the kernel
python -m ipykernel install --user --name trial_env --display-name "Python 3 (venv)"

# Launch Jupyter
jupyter notebook
```

Execute notebooks in this order:
1. `notebooks/01_data_cleaning_eda.ipynb`
2. `notebooks/02_conversion_driver_analysis.ipynb`
3. `notebooks/03_descriptive_analytics.ipynb`

> **Note:** Each notebook saves its output as a parquet file used by the next. Run them sequentially.

## The Three Tasks

### Task 1 — Explore, Clean & Define Goals
**Notebooks:** `01_data_cleaning_eda.ipynb`, `02_conversion_driver_analysis.ipynb`

- 10 documented data quality checks
- Full cleaning pipeline (deduplication, datetime parsing, trial-window filtering)
- Derived features: `trial_day`, `days_to_convert`, `module`
- 6 EDA visualisations
- Conversion driver analysis using:
  - Mann-Whitney U & Chi-squared statistical tests
  - Point-Biserial correlation
  - Lift & Odds Ratio analysis (per activity)
  - Random Forest + SHAP feature importance
  - K-Means engagement segmentation
- **5 Trial Goals defined** (see below)

### Task 2 — SQL Data Models
**Directory:** `sql/`

Two mart-layer tables following dbt conventions:

| Table | Grain | Description |
|-------|-------|-------------|
| `fct_trial_goals` | One row per org per goal | Tracks whether each org completed each trial goal |
| `fct_trial_activation` | One row per org | Flags orgs that completed all goals (fully activated) |

### Task 3 — Descriptive Analytics & Product Metrics
**Notebook:** `03_descriptive_analytics.ipynb`

- Conversion rate, time-to-convert, retention curves
- Module adoption rates
- Feature funnel analysis
- Actionable recommendations for the product team

## Trial Goals Defined

Based on statistical analysis, ML feature importance, and lift analysis:

| Goal | Behaviour | Evidence |
|------|-----------|----------|
| **G1 — Scheduling Setup** | Created ≥1 shift AND set availability | Top SHAP feature; highest lift |
| **G2 — Schedule Engagement** | Viewed schedule ≥3 times | High frequency among converters |
| **G3 — Team Communications** | Sent ≥1 team message | Strong Chi-squared signal |
| **G4 — Punch Clock Activated** | Clocked in/out at least once | Signals operational go-live |
| **G5 — Sustained Engagement** | Active on ≥5 distinct trial days | Strongest overall predictor |

**Trial Activation** = completing ALL 5 goals within the 30-day trial window.

> These goals are data-grounded hypotheses. Completion rates and thresholds should be monitored and refined as more data accumulates.

---

## Key Findings

- **966 organisations** trialled the platform; **206 converted (21.3%)**
- **Scheduling dominates** — 92% of all events are scheduling-related
- **Converters are 5x more active** — median 8 active days vs. 2 for non-converters
- **Multi-module users convert at higher rates** — using ≥3 modules strongly predicts conversion
- **Early engagement matters** — converters fire their first event significantly earlier

## Dataset Schema

| Column | Type | Description |
|--------|------|-------------|
| `organization_id` | string | Unique org identifier |
| `activity_name` | string | Product activity performed |
| `timestamp` | datetime | When the activity occurred |

| `converted_at` | datetime | Timestamp of conversion (NaT if not converted) |
